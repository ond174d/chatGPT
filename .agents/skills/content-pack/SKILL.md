# コンテンツ一式の作成

成果物は**構成案ではなく完成品**。台本は読み上げられる状態まで、公開用テキストはそのまま貼れる状態まで書く。

## 0. 進め方 — astra-riding を適用する

作業の進め方はここでは再定義しない。[../astra-riding/SKILL.md](../astra-riding/SKILL.md) の
判断ループに従う。この分野で特に効くのは次の 5 つ。読めない場合はこの要約で足りる。

1. **完成品まで書く。** 「台本を作って」は構成案の依頼ではない。実際に話す文まで書き切る。
2. **結果を変える質問だけ先に聞く。** 尺、視聴者、目的。これらは全体を左右する。ただし**答えを待つ間も手を止めない**。
3. **推測できることは決めて、前提として伝える。** 決めた前提は納品時に列挙する。
4. **書く事実には裏づけを持つ。** 数字、日付、価格、統計、引用は、このセッションで確認できたものだけを断定形で書く。確認できないものは `[要確認]` を付けて公開前に潰す。**それらしい数字を作らない。**
5. **納品前に確かめる。** 手順は [references/checklist.md](references/checklist.md)。

## 1. 最初にすること — ハウススタイルの確認

**書き始める前に必ず実行する。**

```bash
python3 .agents/skills/content-pack/scripts/load_house_style.py
```
> Windows では `python3` を `py -3`(ランチャーが無ければ `python`)に読み替える。
> `install.py` は自動で判定し、`--python` で明示指定もできる。


既存のプロファイル(文体規定、構成テンプレート、禁止用語、対象読者)が見つかれば、
**それがこのスキルの一般則より優先する**。文体注入スキルがあれば実行して文体を取得する。
このスキルが持つのは型(構成、媒体別ルール、尺、文字数)と検証で、文体はプロファイル側に委ねる。

見つからなければ汎用モードで、同梱の一般則で書く。
詳細と、5 ブロック構成テンプレートへの対応は [references/house-style.md](references/house-style.md)。

## 2. 次に確定する 5 項目

| 項目 | 分からないときの既定 | 影響 |
| --- | --- | --- |
| 尺・文字数 | 長尺 8〜10 分 / ショート 45 秒 | 章数、密度 |
| 視聴者・読者 | そのテーマの初心者 | 前提知識、用語、たとえ |
| 目的 | 理解してもらう | 結論の出し方、CTA |
| 話者・人称 | プロファイルの規定。無ければ一人称「僕」 | 語尾、距離感 |
| 必要な成果物 | 台本 + タイトル + 概要欄 | 作る点数 |

尺と視聴者だけは、外すと全部書き直しになる。ここは早めに選択式で聞く。他は決めて進めてよい。

## 3. 手順

### Step 1 — 素材を集める

使う事実を先に固める。**裏づけの取れなかった論点を骨格に置かない。** 後で消すと構成が崩れる。

### Step 2 — 骨格を決める

プロファイルの構成テンプレートがあればそれを使う([house-style.md](references/house-style.md) 4 節)。
無ければ尺から逆算して章を割る。配分とフックの型は [references/structure.md](references/structure.md)。
動画の種類ごとの骨格は [references/formats.md](references/formats.md)。

### Step 3 — フックを 3 案書く

冒頭で視聴者は残るか去るかを決める。フックだけは複数案を書き、最良の 1 案を採用し、
残りを納品時に代案として添える。

### Step 4 — 台本を話し言葉で書く

読み上げ原稿として書く。書き言葉のまま書かない。詳細は [references/delivery.md](references/delivery.md)。
画面に出すものは `[テロップ: ...]` `[B-roll: ...]` `[間]` で指示し、ナレーションと混ぜない。
**文体はハウススタイルが優先する。** 一般則と食い違ったらプロファイルに従う。

### Step 5 — 尺を見積もって調整する

```bash
python3 .agents/skills/content-pack/scripts/script_stats.py 台本.md --target 600
python3 .agents/skills/content-pack/scripts/script_stats.py 台本.md --target 45 --short
```

超過していれば削る。足りなければ水増しではなく内容を足す。

- 話速の既定は日本語 340 字/分、英語 150 語/分。実測ではなく目安なので `--cpm` `--wpm` で変える。
- 角括弧の指示、HTML コメント、コードブロック、フロントマターは尺に含めない。引用行と表の中の文字は含める。
- 対談台本は `--speakers 進行役,ゲスト` で行頭の話者名を除く。

### Step 6 — 公開用テキストを作る

タイトル、概要欄、チャプター、固定コメント、SNS 投稿、キャプション、サムネイル文言。
媒体ごとに別の文章として書く。同じ文を貼り回さない。書き方と上限は
[references/derivatives.md](references/derivatives.md)、雛形は `assets/template-derivatives.md`。

```bash
python3 .agents/skills/content-pack/scripts/copy_check.py 派生物.md --platform auto
python3 .agents/skills/content-pack/scripts/copy_check.py 投稿.txt --platform x
```

文字数の上限、見える範囲、ハッシュタグ数、ハウススタイルの禁止語、言い切り型に対する弱い語尾を点検する。
X は日本語を 2 単位として数える。

### Step 7 — 確かめて納品する

[references/checklist.md](references/checklist.md) を通してから渡す。納品物は次の 5 点。

- 完成台本(尺の見積り付き)
- 公開用テキスト一式
- 置いた前提の一覧
- 未確認の事実があれば、その一覧と確認方法
- フックの不採用案

## 4. やってはいけないこと

- 構成案や箇条書きで止めて「あとは肉付けしてください」と渡す。
- ハウススタイルを確認せずに一般則で書く。既存の声から外れた原稿は使えない。
- 統計、売上、シェア、日付、価格を確認せずに具体的な数字で書く。視聴者に届く嘘を作らない。
- 台本の要約をそのまま概要欄にも X にも貼る。媒体ごとに読者の状況が違う。
- 冒頭で「今日は〜について話していきます」だけを言って本題に入らない。
- 「登録お願いします」を、視聴者が価値を受け取る前に置く。
- 用意できない素材(権利のない映像や音源、撮影できない場所)を前提にする。
- 確証がないのに、語尾だけ言い切りに変えて断定する。**強めるのではなく主張を落とす。**

## 5. 既存原稿を直すとき

改稿は書き直しではなく**差分**で返す。何をどう変えたか、なぜ変えたかが分かる形にする。
元の文体は保つ。フックだけ、尺だけ、概要欄だけという部分依頼なら、そこ以外に手を入れない。
入れる必要があると判断したら、理由を添えて提案し、実行は相手に委ねる。
