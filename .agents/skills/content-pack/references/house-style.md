# ハウススタイルに乗る

このスキルは 2 つのモードで動く。作業を始める前に、どちらかを確定する。

```bash
python3 .agents/skills/content-pack/scripts/load_house_style.py
```

| モード | 条件 | 文体の決め方 |
| --- | --- | --- |
| ハウス | 既存のプロファイルが見つかった | プロファイルの規定に従う。文体注入スキルがあればそれに委ねる |
| 汎用 | 見つからない | このスキル同梱の一般則([delivery.md](delivery.md))で書く |

## 目次

1. 責務の分離
2. 検出するもの
3. ハウスモードでの進め方
4. 構成テンプレートの対応
5. 禁止語と語尾の扱い
6. 汎用モードとの違い

## 1. 責務の分離

Second Brain 形式のプロファイルを持つ環境では、**文体はプロファイル、型はワークフロー**という
分離がすでに設計されている。このスキルはその分離を壊さない。

| レイヤー | 担当 | このスキルの扱い |
| --- | --- | --- |
| 文体(トーン、語尾、語彙、禁止語) | プロファイルと文体注入スキル | 読み込んで従う。上書きしない |
| 型(構成、媒体別ルール、尺、文字数) | このスキル | ここで持つ |
| 検証(上限、禁止語、尺) | このスキルのスクリプト | ここで持つ |

文体注入スキルが存在するときは、執筆前にそれを実行して文体コンテキストを取得する。
`load_house_style.py` が実行コマンドを表示する。

## 2. 検出するもの

`load_house_style.py` はカレントから上へ辿り、次のいずれかがあるディレクトリを起点とする。

- `00_システム/00_UserProfile/` — 一人称、二人称、基本トーン、NGワード、禁止用語、構成テンプレ
- `コンテキスト.md` — ミッション、対象読者、コンテンツ構成テンプレ、言語運用ポリシー
- `.agent/skills/my_writer/` — 文体注入スキル

拾えるのは決まった書式の項目だけ。**拾えなかった規定は自分で読む。**
スクリプトの出力を、プロファイル本文を読まない口実にしない。

## 3. ハウスモードでの進め方

1. `load_house_style.py` を実行し、検出結果を確認する。
2. 文体注入スキルがあれば実行し、出力された文体規則を読む。
3. プロファイルの構成テンプレートに従って骨格を決める(次節)。
4. 対象読者の規定を確認する。非 IT 層向けなら、禁止用語の言い換えが必須になる。
5. 書き上げたら `copy_check.py` と `script_stats.py` を通す。禁止語と弱い語尾はここで機械的に落ちる。

プロファイルの規定とこのスキルの一般則が食い違ったら、**プロファイルが勝つ**。
たとえば delivery.md は「〜です」調を前提に書いているが、プロファイルが「〜だ」の言い切り型を
定めているなら言い切り型で書く。ユーザーの明示的な指示は、その両方より優先する。

## 4. 構成テンプレートの対応

プロファイルが構成テンプレートを持つなら、それを使う。Hook / Prove / Teach / Entertain / Action
の 5 ブロックの場合、[structure.md](structure.md) の一般型とは次のように対応する。

| 5 ブロック | 役割 | 一般型での対応 |
| --- | --- | --- |
| Hook | 続きを見る理由を渡す | フック |
| Prove | 話す資格があること、主張が事実であることを示す | 導入の一部(一般型には独立ブロックがない) |
| Teach | 中身を渡す | 本編 |
| Entertain | 飽きさせない。具体例、失敗談、意外性 | 本編の一部(一般型には独立ブロックがない) |
| Action | 次の行動を 1 つ | CTA |

一般型に無いのは **Prove** と **Entertain**。この 2 つを落とすと、型に従ったことにならない。

- **Prove**: 実績、実測、事例、一次情報。「なぜあなたの話を聞くのか」への答え。裏づけのない Prove は書かない。
- **Entertain**: 教える区間の合間に置く。具体例、想定外の結果、失敗の共有。ここが無いと Teach が続いて離脱する。

尺配分の目安(10 分の場合): Hook 15 秒、Prove 45 秒、Teach 5〜6 分、Entertain は Teach の合間に
合計 1〜2 分、Action 30 秒。Entertain を独立した章にせず、Teach の章に織り込んでもよい。

## 5. 禁止語と語尾の扱い

プロファイルの禁止用語は、対象読者によって適用範囲が変わることがある。たとえば
「非エンジニア相手には API・Python などを使わず『仕組み』『自動化』に言い換える」といった条件付きの規定。

- 条件を確認せずに一律で置換しない。読者がエンジニアなら使ってよい場合がある。
- 迷ったら厳しい側に倒す。言い換えても意味が通るなら言い換える。
- `copy_check.py` は条件を判断できない。検出された語を 1 つずつ、読者に照らして判断する。

語尾も同じ。言い切り型を定めるプロファイルでは「〜と思います」「〜かもしれません」は弱い。
ただし推測を断定に変えてはならない。**確証がないなら、語尾を強めるのではなく主張を落とす。**

## 6. 汎用モードとの違い

プロファイルが無い環境では、このスキルが文体も型も持つ。その場合でも、次は必ず確認する。

- 既存の作品があるなら、それに合わせる。合わせる先が無いときだけ一般則を使う。
- 決めた文体方針を、納品時に前提として 1 行で伝える。
