# YouTube 台本作成

成果物は**構成案ではなく完成原稿**。カメラの前で、またはナレーション収録でそのまま読める状態まで書く。

## 0. 進め方 — astra-riding を適用する

作業の進め方はこのスキルでは再定義しない。[../astra-riding/SKILL.md](../astra-riding/SKILL.md) の
判断ループに従う。台本作成で特に効くのは次の 5 つ。読めない場合はここに書いた要約で足りる。

1. **完成原稿まで書く。** 「台本を作って」は構成案の依頼ではない。見出しと箇条書きで止めず、実際に話す文まで書き切る。長い動画でも途中で切り上げない。
2. **結果を変える質問だけ先に聞く。** 尺、視聴者、チャンネルの目的、話者、既存の文体。これらは台本全体を左右するので最初に確認する。ただし**答えを待つ間も手を止めない**。分かる範囲で書き始め、返答が来たら合わせる。
3. **推測できることは決めて、前提として伝える。** 呼称、テロップの粒度、章立ての数、想定機材。決めた前提は納品時に列挙する。
4. **台本に書く事実には裏づけを持つ。** 数字、日付、製品仕様、引用、統計は、このセッションで確認できたものだけを断定形で書く。確認できないものは台本から外すか、`[要確認]` を付けて視聴者に届く前に潰せるようにする。**それらしい数字を作らない。**
5. **納品前に確かめる。** 尺の見積り、依頼項目の網羅、事実の裏づけ、話し言葉として読めるか。手順は [references/checklist.md](references/checklist.md)。

## 1. 最初に確定する 5 項目

| 項目 | 分からないときの既定 | 台本への影響 |
| --- | --- | --- |
| 尺 | 長尺 8〜10 分 / ショート 45 秒 | 章数、1 章あたりの文字数、情報の密度 |
| 視聴者 | そのテーマの初心者 | 前提知識、用語の噛み砕き方、たとえの選び方 |
| 動画の目的 | 理解してもらう(教育) | 結論を先に出すか、引っ張るか。CTA の中身 |
| 話者・人称 | 一人称「僕」、視聴者は「みなさん」 | 語尾、距離感、敬語の度合い |
| チャンネルの文体 | 既存動画があれば合わせる | テンション、定型の挨拶、決め台詞 |

尺と視聴者だけは、外すと全部書き直しになる。ここは早めに選択式で聞く。他は決めて進めてよい。

## 2. 手順

### Step 1 — 素材を集める

テーマについて、台本で使う事実を先に固める。手元の資料、渡されたリンク、調べられるなら調査。
**この段階で裏づけの取れなかった論点は、台本の骨格に置かない。** 骨格に据えてから消すと構成が崩れる。

### Step 2 — 骨格を決める

尺から逆算して章を割る。配分の目安と型は [references/structure.md](references/structure.md)。
動画の種類ごとの骨格(解説、レビュー、チュートリアル、ニュース、対談、vlog)は
[references/formats.md](references/formats.md)。

### Step 3 — フックを 3 案書く

冒頭 15 秒で視聴者は残るか去るかを決める。フックだけは複数案を書き、最良の 1 案を本文に採用し、
残りを納品時に代案として添える。作り方は [references/structure.md](references/structure.md) の 2 節。

### Step 4 — 本文を話し言葉で書く

読み上げ原稿として書く。書き言葉のまま書かない。詳細は [references/delivery.md](references/delivery.md)。

- 一文を短く。息継ぎできない長さにしない。
- 主語と述語を近づける。修飾の入れ子を避ける。
- 漢語より和語。「実施する」より「やる」。ただしチャンネルの文体が硬いなら合わせる。
- 数字は口に出せる形で書く(「約 3 割」「およそ 1 万円」)。
- 画面に何を出すかを `[テロップ: ...]` `[B-roll: ...]` `[画面収録: ...]` で指示する。ナレーションと指示を混同させない。

### Step 5 — 尺を見積もって調整する

```bash
python3 .agents/skills/youtube-script/scripts/script_stats.py 台本.md --target 600
```

ナレーション部分だけを数えて秒数を出し、章ごとの配分と目標尺との差を表示する。
超過していれば削る。足りなければ、水増しではなく内容を足す。

- 話速の既定値は日本語 340 字/分、英語 150 語/分。実測ではなく目安なので、話者に合わせて `--cpm` `--wpm` で変える。
- 角括弧の指示、HTML コメント、コードブロック、フロントマターは尺に含めない。引用行と表の中の文字は読み上げる可能性があるので**含める**。除きたければコメントか角括弧に入れる。
- 対談など話者名を行頭に置く台本は `--speakers 進行役,ゲスト` で指定する。指定した名前だけを剥がすので、`結論:` のような書き出しは削られない。

### Step 6 — 確かめて納品する

[references/checklist.md](references/checklist.md) を通してから渡す。納品物は次の 4 点。

- 完成台本(テンプレートは `assets/template-long.md` / `assets/template-short.md`)
- 尺の見積り(全体と章ごと)
- 置いた前提の一覧
- 未確認の事実があれば、その一覧と確認方法

## 3. やってはいけないこと

- 構成案や箇条書きで止めて「あとは肉付けしてください」と渡す。
- 統計、売上、シェア、日付、価格を確認せずに具体的な数字で書く。視聴者に届く嘘を作らない。
- チャンネルの文体を無視して、一般的な YouTuber 風の定型に寄せる。
- 冒頭で「今日は〜について話していきます」だけを言って本題に入らない。名乗りと挨拶で 30 秒使わない。
- 全章を同じ密度で書く。山と谷を作らないと最後まで持たない。
- 「登録お願いします」を、視聴者が価値を受け取る前に置く。
- 台本に書けない演出(実際に用意できない素材、権利のない映像や音源)を前提にする。

## 4. 既存台本を直すとき

改稿の依頼は、書き直しではなく**差分**で返す。何をどう変えたか、なぜ変えたかが分かる形にする。
元の文体は保つ。フックだけ、尺だけ、CTA だけ、という部分依頼なら、そこ以外に手を入れない。
入れる必要があると判断したら、理由を添えて提案し、実行は相手に委ねる。
