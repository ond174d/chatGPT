# Astra 自体に乗る — Codex での設定と移行

GPT-6 Astra を Codex で使うときの設定と、旧モデル(GPT-5.6 Sol など)から切り替えるときの見直し項目。
数値や仕様は 2026 年 9 月時点の公開情報にもとづく。変わる可能性があるので、迷ったら公式ドキュメントで確認する。

## 目次

1. 最小設定
2. reasoning effort の選び方
3. コンテキスト管理(context notes)
4. 切り替え時に見直す 4 項目
5. AGENTS.md とスキルの監査
6. Astra を使わない場合
7. 役割分担の原則

## 1. 最小設定

`~/.codex/config.toml`:

```toml
model = "gpt-6-astra"
model_reasoning_effort = "high"   # low | medium | high | xhigh | max
```

- CLI から一時的に指定するなら `codex -m gpt-6-astra`。
- Codex CLI 0.153.0 以降が必要。
- API では `reasoning.effort` に `none` を指定できない(HTTP 400)。

## 2. reasoning effort の選び方

| レベル | 向いている作業 |
| --- | --- |
| low | 定型変換、軽い整形、コストを最優先したいバッチ |
| medium | 1 往復で終わる作業: 抽出、分類、下書き、差分レビュー |
| high | ツールを何度も呼ぶ長めの作業。コーディングの既定値 |
| xhigh / max | high で失敗率を実測した特定の難所: 設計判断、難しいデバッグループ |

原則は「実タスクで組んだ評価を安定して通る最低レベルを使う」。
高いレベルは品質・遅延・コストのダイヤルであって、常に良くなる保証ではない。
上げる理由を具体的な失敗で言えないなら上げない。

## 3. コンテキスト管理(context notes)

Astra では、コンテキストが埋まったときに毎回要約に圧縮する代わりに、検索可能なノートを
ウィンドウをまたいで保持できる。以前のウィンドウも検索対象に残るので、ノートに書かれなかった
要件やテスト結果も後から探せる。

実験的機能として次で有効化できる(対象プランのセッションのみ):

```toml
[features.context_management]
experimental_mode = true
```

使いどころは、長い同種のタスク(大規模リファクタ、長時間のデバッグ)。短いタスクでは既定のままでよい。

## 4. 切り替え時に見直す 4 項目

1. **履歴管理** — 既定のままで始め、長い同種タスクに限って context notes を試す。
2. **指示ファイル** — Astra は指示追従が強く、曖昧さや矛盾に敏感。古い禁止事項・重複・衝突する記述を削る。
3. **推論強度** — 既定は high。上げるのは失敗を実測した作業だけ。
4. **速度** — 標準速度を基準にし、必要な作業だけ変える。

## 5. AGENTS.md とスキルの監査

Astra は「常に確認する」「必ず質問してから」「〜してはならない」のような古い記述を忠実に守るため、
それが原因で作業が止まる。次の手順で洗い出す。

1. `scripts/audit_instructions.py` を実行し、承認を強制する表現や絶対禁止の表現を一覧にする。
2. 各記述について「今も必要か」「不可逆操作の保護か、それとも昔の癖か」を判断する。
3. 不要なものは削除、必要なものは「何が不可逆なので確認が要るか」を書き添える形に直す。
4. 同じ内容が AGENTS.md と SKILL.md の両方にある場合は片方に寄せる。

```bash
python3 .agents/skills/astra-riding/scripts/audit_instructions.py .
```

## 6. Astra を使わない場合

GPT-5.6 Sol / Terra で Astra の振る舞いを再現する構成は [astra-on-sol-terra.md](astra-on-sol-terra.md) にまとめてある。
`scripts/install.py --target codex` がプロファイル(`astra-sol` / `astra-terra`)、hooks、検証サブエージェントを導入する。

## 7. 役割分担の原則

- **AGENTS.md** — リポジトリ全体に常に効く恒久ルール。
- **スキル(SKILL.md)** — 繰り返す手順の束(リリース前チェック、ログ解析、PR 作成など)。
- **MCP** — 外部システムへの接続。

スキルの置き場所は、リポジトリなら `.agents/skills/<name>/`、個人用なら `~/.agents/skills/<name>/`。
同名なら プロジェクト > ユーザー > システム の順で優先される。
